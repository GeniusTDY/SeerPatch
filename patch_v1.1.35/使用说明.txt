赛尔号 精灵美术修复累积补丁（v1.1.35）
======================================

本补丁是「累积补丁」：已包含此前全部文件与修改，
含 3041 / 3042 / 3043 的真实逐帧战斗动画、对战立绘放大、
待机连续性修正与属性图标补全。
已装 v1.1.11 及以后版本的用户，只装这一个包。

【v1.1.35 修复：技能动画“变形”（放技能瞬间整只缩小）+ 3042/3043 待机提速】

1) 技能动画为什么看起来“变形”
   待机是整张贴图按自身像素尺寸显示，攻击是按 trim 尺寸显示，
   两者必须使用同一个像素比例。实测对照：
     官方 3040：待机贴图 234x332，攻击首帧 238x331 —— 比例 1.00；
     我们上一版：待机美术高 605 / 612 / 614，
                 攻击首帧只有 414 / 407 / 402 —— 比例只有 0.66。
   所以一放技能，精灵会突然缩小约三分之一，观感上就是压扁/变形。
   （此前几版把攻击倍数 1.30 / 0.70 / 0.62 当成“比例”，
     但待机后来已经放大到 2.375 / 1.05 / 0.946，两者没有同步。）

2) 本版修法
   - 9 段攻击动画全部按各自待机的像素比例重绘：
       3041：1.625 -> 2.374（首帧 562x604）
       3042：0.70  -> 1.053（首帧 470x612）
       3043：0.62  -> 0.947（首帧 936x614）
     与各自待机的美术高度（605 / 612 / 614）一致，放技能不再缩小；
   - 帧映射、帧数（88 / 53 / 56）、trim 的帧间位移完全不变，
     只同步贴图 / Sprite / trim 的尺寸（trimX 保持中心、trimY 保持底边）；
   - 待机 3042_1 / 3043_1 由 30fps（0.70 秒）提速到 60fps（0.35 秒），
     与官方 3040_1 完全一致；3041_1 本版未改动。

3) 代价
   fight3041 资源包由 25.9 MB 增至 48.5 MB（攻击贴图约 2.2 倍面积），
   补丁包相应变大；动画帧数、时序与 trim 位移均未改变。

【v1.1.34 修复：3043 待机立绘改为加宽画布（不再缩小）】

1) 结论修正
   v1.1.33 把 3043 整体缩小塞进 586×625 画布，方向错了。
   实测对战里玩家侧与敌人侧的同名精灵（雷神雷伊）显示尺寸几乎相同，
   而两侧预制体的框（412.5×486.25 / 330×389）相差 25%，
   说明立绘显示大小由「贴图本身的画布尺寸」决定，不是那个框。
   官方「古代机械巨人」的立绘几乎占满左半屏，也远超该框。

2) 本版修法
   - 保持待机美术高度（约占画布高 98.7%，617px），不再缩小；
   - 画布由 586×625 加宽到 938×625，完整容纳 988×656 的翼展，
     左右各留 4px，无任何裁切；
   - 21 帧逐帧重绘，帧序与时序不变。
   贴图按自身尺寸显示后，3043 的待机立绘会明显变大，
   左右展开约 930px，不会再出现两侧硬切口。

3) 说明
   3041 / 3042 的画布仍是 586×625（本身没有裁切），本版未改动；
   3042 / 3043 的合包方式、catalog 均与 v1.1.32 相同。

【v1.1.33（已作废）：3043 待机整体缩小】
   该版把 3043 等比缩小到 586 宽以消除裁切，会导致立绘明显变小，

【v1.1.32 修复：3042 / 3043 对战仍提示「战斗资源加载失败」】

1) 前两版为什么没修好
   v1.1.30 / v1.1.31 都是给 3042、3043 各新增一个
   fight3042_…bundle / fight3043_…bundle 文件塞进 APK。
   游戏是从 APK 的 assets/aa/Android 直接读取资源包的，
   而 Android 只能对 zip 里「未压缩（存储）」的条目做随机读取。
   新增的条目一旦被压缩工具按 Deflate 写入、或与原包条目属性不一致，
   运行时就会打不开这个资源包——表现就是进度走到一半左右后
   提示「战斗资源加载失败」。
   而 APK 里本来就有的 fight3041_…bundle 一直是「覆盖同名文件」，
   条目属性不变，所以 3041 始终正常。

2) 本版修法：不再新增文件，直接并进已有的 3041 资源包
   - 把 3042、3043 的 4 段动画、4 段 trim、218+218 张贴图
     全部并入 APK 原有的 fight3041_…bundle（只替换这一个文件）；
   - catalog.json 里 3042 / 3043 的动画与 trim 条目，
     改为指向 fight3041 这个本来就存在的资源包；
   - 不再需要 fight3042 / fight3043 两个新文件（本包已删除）。
   这样整个补丁只需覆盖 APK 里已有的同名文件，
   不再依赖「往 APK 里新增条目」这一步。

3) 修复后自检结果
   - 合并包：1334 个对象、PathID 严格升序、无外部依赖，
     24 条容器、464 条预载表，全部引用可解析；
     12 段 trim / 12 段动画齐全（21 / 88 / 53 / 56 帧），
     654 张贴图全部可解码；
     3041 原有 8 条容器顺序不变（不影响 3041 的战斗）；
   - catalog：23787 个 key、14395 条 entry、13070 个 internalId，
     3042 / 3043 的 12 个资源键（8 动画 + 4 trim）全部指向
     fight3041 包，provider / 依赖哈希 / 条目类型与 3041 完全一致；
   - 已确认 catalog 中不再出现 fight3042 / fight3043 的包键。

4) 安装注意（重要）
   - 本版只覆盖同名文件；如果之前装过 v1.1.30 / v1.1.31，
     APK 里多出来的 fight3042_… / fight3043_… 两个文件可以删掉
     （不删也不影响，本版 catalog 已不再引用它们）；
   - 覆盖文件时压缩方式请保持「存储 / Store（不压缩）」；
   - 完整步骤见文末【安装】。

【v1.1.31 修复（历史）：属性图标不显示】
   v1.1.30 给两个新包用了很大的负数 PathID、并追加在对象表末尾，
   SerializedFile 的对象表因此不是升序，整个资源包被判为损坏，
   连带 pettypebig（属性图标图集）一起加载失败，
   所以所有精灵的属性图标都不显示。
   v1.1.31 改为「最大 PathID + 1」的正数编号、保存前排序，
   并从 v1.1.29 原始包重建 pettypebig；属性图标已恢复显示。
   该版战斗包仍是新增文件，对战加载问题由 v1.1.32 解决。

【v1.1.29 内容：修掉待机里那一处水花跳变】

1) 问题在哪
   v1.1.28 把待机改成 21 帧矢量插值后，身体各部件已经连续，
   但水花（第 11 号部件）的交叉淡化写错了：
   淡出用的图案被固定成 A 姿势的 80 路径大水花。
   于是 D→E、B→C 这两段摆到半程（u≈0.5）时，水花会突然
   跳回 A 的大水花——正好是呼吸摆到最边上那一下，
   看起来就是唯一一处“衔接不连贯”。

2) 本版修法
   淡出图案改用「这一段起点姿势自己的水花」：
     9→19 用 A 的水花，19→21 用 D 的水花；
     9→12 用 A 的水花，12→14 用 B 的水花。
   两端之间做交叉淡化，水花随姿势连续变化，中途不再回跳。
   另外把待机帧底边对齐的 alpha 阈值由 16 提到 32，
   避免极淡水花经 ASTC 压缩后底行消失、脚底悬空 1px。

3) 未改动的部分
   21 帧、30fps、0.70 秒周期、画布 586x625、ART_SCALE 2.376、
   playerPet 框、攻击贴图/trim/clip 全部与 v1.1.28 相同，
   只替换待机 21 张贴图的内容。

【v1.1.28 内容：待机动画改为 21 帧全插值的连续呼吸】

1) 为什么 v1.1.27 还是不够连贯
   重新核对官方 3041_fight.swf 的 pet 时间轴第 9~30 帧后发现：
   官方待机本身也不是逐帧动画，而是 5 个姿势各停留 2~3 帧：
      9,10,11 = A    12,13 = B    14,15 = C
      16,17,18 = A   19,20 = D    21,22 = E
   v1.1.27 只是去掉了段间硬切，21 个关键帧里仍然只有 5 个不同姿势，
   所以看上去还是「一停一顿」的定格动画。

2) 本版做法：在矢量层面生成中间姿势
   对比各姿势的 SVG 后发现，身体只是 12 个矢量部件分别做了小角度旋转
   （A 为 0°，B 约 -2.8°，C 约 -5.5°，D 约 +3.3°，E 约 +6.8°），
   各姿势的部件路径完全一致。因此本版对每个部件的旋转/缩放/位移
   做插值，直接渲染出 21 个互不相同的中间姿势：
      - 21 帧、30fps、0.70 秒周期全部与 v1.1.27 相同；
      - 相位用正弦曲线：最左/最右自然减速，过中点速度最快，
        首尾无缝，读起来是匀速呼吸而不是机械往返；
      - 因为插值发生在矢量层，边缘和线条保持清晰，没有位图混合的重影。
   第 11 号部件是逐姿势变化的水花特效（无法用变换插值），
   对它的位置/旋转做同样插值、图案在两种水花之间交叉淡化，
   水花本身是流动的半透明效果，观感就是水在流动。

3) 显示尺寸没有变化
   待机画布仍是 586x625，ART_SCALE 仍是 2.376，playerPet 仍是
   v1.1.26 的 412.5x486.25；本版只改待机贴图内容，不改大小与框位。
   攻击贴图、trim、clip 帧数与采样率均与 v1.1.27 一致。

【v1.1.27 内容：技能不再明显缩小 + 待机不再闪回】

1) “使用技能时立绘会缩小”——官方原版确实也会小一点，但没这么夸张
   实测官方 3040：
     待机 234x332 贴图放进 330x389 的 playerPet 框（可见约 330x386）；
     攻击 trim 238x331。
     高度比 331/386 ≈ 0.86，也就是官方技能时会缩到约 86%。
   v1.1.26 的 3041：
     待机约 396x471，攻击仍是 308x331 → 高度比 0.70，缩得太明显。
   本版把攻击 3041_2/3/4 的画布与 trim 同步 ×1.25：
     首帧 308x331 -> 385x414。
   与待机 471 的高度比 414/471 ≈ 0.88，基本回到官方的 0.86，
   技能时不会再出现“突然变小一圈”的观感。
   攻击 clip 的帧数、采样率、PPtr 映射均保持原样，只改贴图/Sprite/trim。

2) 待机“不连贯”的真正原因与修复
   官方 SWF 的 pet 时间轴第 9~30 帧并不是一段连续动画，而是 3 段拼接：
      9-15   A→B→C（左摆）
      16-22  A→D→E
      23-30  A→F→G→F
   段与段之间是硬切换（C→A、E→A），官方 Unity 的 21 帧待机也是
   逐帧居中后直接拼接，所以原版本身就带两次“闪回”。
   v1.1.26 沿用这个拼接序列，因此看起来仍然不连贯。
   本版只用 A/B/C/D/E 五个姿势做一个完整呼吸循环：
      A3, B2, C3, B2, A3, D2, E2, D2, A2
   首尾都是 A，循环无缝；左摆→回正→轻微右倾→回正，
   不再有段间硬切。
   节奏同步为 30fps / 0.70 秒（21 个关键帧，60Hz 下每帧 2 次刷新，
   比以前 25fps 的 2/3 次刷新交替更均匀）。

3) 关于“playerPet 显示框是所有玩家侧精灵共用”的核查
   结论：这个判断成立，不是“歪打正着”。
   - 官方 3040 的待机同样是 234x332、同样没有 3040_1.trim；
   - catalog 里 1058 只精灵只有 _2/_3/_4 三段攻击 trim，
     没有任何精灵的 _1 待机 trim（3041_1 / 3042_1 / 3043_1
     是本补丁自己加的，游戏不会读取）；
   - 所以待机显示尺寸确实由 playerPet 这个共用 RectTransform 决定。
   - v1.1.26 把它放大 1.25 倍，资源层面会同时放大所有玩家侧精灵的待机；
     如果实测其他精灵没有变化，说明运行时还有额外逻辑，但资源层面是共用的。
   - 本版没有再次修改 playerPet，仍是 v1.1.26 的 412.5x486.25；
     待机画布仍是 586x625，因此三只精灵的待机显示尺寸一致，
     本版只修正动画序列与技能时的大小比例。
